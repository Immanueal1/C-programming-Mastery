# 🤝 Contributing to C-Programming-Mastery

Thank you for your interest in contributing to **C-Programming-Mastery**! 

This repository is primarily a personal learning journey, educational resource, and portfolio project maintained by **Immanueal**. To maintain high documentation quality and curriculum integrity, please review the following contribution guidelines before submitting Pull Requests or opening Issues.

---

## 💡 Types of Contributions Accepted

We welcome contributions that improve the quality, accuracy, and accessibility of the repository:

- 🐛 **Bug Fixes**: Fixing syntax errors, compilation warnings, or broken code snippets.
- 📝 **Documentation Improvements**: Correcting typos, refining theoretical explanations, or improving markdown formatting.
- 💡 **Practice Problem Enhancements**: Suggesting edge cases, improving sample inputs/outputs, or fixing hints.
- 🎨 **Visual Notes Refinements**: Reporting errors or ambiguities in diagrams and cheat sheets.

> ⚠️ **Note**: Because this repository tracks a structured personal curriculum, unsolicited additions of entirely new chapters or major structural changes may be declined. Please open an Issue to discuss proposals before working on large pull requests.

---

## 🛠️ Contribution Workflow

### 1. Issue First
Before submitting non-trivial changes, please search existing issues or open a new issue describing the problem or improvement.

### 2. Fork & Branch
Fork the repository and create a descriptive feature branch:
```bash
git checkout -b fix/chapter-01-typo
```

### 3. Coding & Documentation Standards
- **C Standard**: Write clean C code conforming to C99 / C11 standards.
- **Compiler Warnings**: Ensure code compiles cleanly with `-Wall -Wextra -std=c11` without warnings.
- **Formatting**: Use consistent 4-space indentation and clean variable naming (`camelCase` or `snake_case`).
- **No Solutions Overwrite**: Do not overwrite starter templates in chapter practice directories with completed solutions unless contributing to dedicated solution branches.

### 4. Commit Messages
Write clear, concise commit messages following standard conventions:
- `docs: fix typo in Chapter 01 README`
- `fix: resolve compiler warning in Chapter 05 recursion example`
- `style: reformat code blocks in theory notes`

### 5. Submit Pull Request
Open a Pull Request against the `main` branch. Provide a detailed summary of your changes and reference any related issue numbers.
